# 🎫 Дискорд-бот с тикетами (русский)

Бот системы тикетов с логами, категориями, панелью создания тикетов, кнопками
управления внутри тикета и панелью администрации. Все команды на русском и
работают через префикс `!`.

## Возможности
- Создание тикетов через выпадающее меню категорий.
- Отдельный канал под каждый тикет; видят только автор, поддержка и администрация.
- Внутри тикета кнопки: **Принять тикет**, **Закрыть тикет**, **Закрыть с причиной**.
- Логи тикетов в отдельный канал + текстовый транскрипт при закрытии.
- 6 категорий по умолчанию: «Заявка на кастом. роль», «Заявка на раздачу
  промокода», «Заявка на модерацию», «Покупка товара», «Организовать розыгрыш»,
  «Другое». Можно менять текст, эмодзи и описание.
- Панель администрации: настройки + статистика.
- Роль администрации настраивается командой `!роль_админ`.
- **Модерация:** баны, разбаны, кики, муты (тайм-ауты), размуты и предупреждения
  (варны с выбором наказания на 3-м) — с логами.
- **Автомод:** авто-мут за спам/флуд и за приглашения в Discord (ссылки `discord.gg`
  и подобные). Обычные ссылки **не** наказываются. Иммунитет у поддержки/администрации,
  у ролей с правом «Управление сообщениями» и у назначенных ролей.
- Красивая интерактивная панель настроек автомода с кнопками-переключателями.
- **🧠 ИИ-собеседник (role play):** упомяните бота (`@бот`) в чате — он ответит
  как ролевой персонаж, который «шарит за мемы» и интернет-культуру. Работает через
  любой OpenAI-совместимый API (OpenAI, Groq, OpenRouter и т.п.). Помнит последние
  реплики в канале, есть антифлуд, вкл/выкл и смена образа персонажа.
- **🌦️ Погода:** команда `!погода <город>` — текущая погода и прогноз на день
  (бесплатный сервис Open-Meteo, **API-ключ не нужен**).
- **🎉 Развлечения и утилиты:** `!мем`, `!аватар`, `!юзер`, `!сервер`, `!кости`,
  `!шар` (магический шар), `!выбери`.

## Токен и конфигурация
Токен читается в таком порядке приоритета:
1. Переменная окружения `DISCORD_TOKEN` (или `TOKEN`) — **рекомендуется для хостинга**.
2. Файл `config.json` (удобно для локального запуска).

Префикс — переменная окружения `PREFIX` или поле `"prefix"` в `config.json` (по умолчанию `!`).

> ⚠️ **Безопасность:** `config.json` и `data.json` добавлены в `.gitignore` и **не**
> должны попадать в репозиторий. Если токен когда-либо оказался в коде или в
> публичном месте — немедленно сбросьте его в Discord Developer Portal (**Bot → Reset Token**).

## 🧠 Настройка ИИ-собеседника
ИИ отвечает на **упоминания** бота. Работает с любым OpenAI-совместимым провайдером —
достаточно задать переменные окружения (или поля в `config.json`):

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `AI_API_KEY` | да (для ИИ) | — | API-ключ провайдера (или `OPENAI_API_KEY`) |
| `AI_BASE_URL` | нет | `https://api.openai.com/v1` | базовый URL API (для Groq/OpenRouter/OmniRoute и т.п.) |
| `AI_MODEL` | нет | `gpt-4o-mini` | модель для ответов (чат) |
| `AI_MODEL_CODING` | нет | = `AI_MODEL` | модель для команды `!код` |
| `AI_IMAGE_MODEL` | нет | — | модель для команды `!картинка` (генерация изображений) |
| `AI_BOT_NAME` | нет | `Ботя` | имя персонажа по умолчанию (role play) |

Без `AI_API_KEY` все остальные функции бота (тикеты, модерация, погода, мемы) работают
как обычно — при упоминании бот лишь подскажет, что ИИ не настроен.

Примеры совместимых провайдеров: **OpenAI** (`https://api.openai.com/v1`),
**Groq** (`https://api.groq.com/openai/v1`), **OpenRouter** (`https://openrouter.ai/api/v1`),
**DeepSeek** (`https://api.deepseek.com`), а также локальный **OmniRoute** (см. ниже).
На сервере ИИ можно выключить командой `!ии выкл` и сменить образ персонажа `!ии_имя <имя>`.

### Модель под цель (чат / кодинг / картинки)
Одна и та же связка ключ+URL может обслуживать несколько моделей. Модель под
конкретную цель задаётся прямо на сервере:

```text
!ии_модель                              — показать текущие модели по всем целям
!ии_модель чат kr/claude-sonnet-4.5     — модель для ответов на упоминания
!ии_модель кодинг kr/qwen3-coder-next   — модель для команды !код
!ии_модель картинка <модель-картинок>   — модель для команды !картинка
!ии_модель <цель> сброс                 — вернуть значение по умолчанию (из окружения)
```

### Авто-выбор модели по задаче
Когда вы упоминаете бота (`@Ботя ...`), он сам определяет цель по тексту и
подставляет нужную модель — не обязательно звать `!код` или `!картинка`:

- просите **код** («напиши функцию…», блок ```` ``` ````) → модель для кодинга
  (например `kr/qwen3-coder-next`) и деловой стиль ответа;
- просите **картинку** («нарисуй…», «сгенерируй изображение…») → модель для
  генерации изображений (если она задана);
- всё остальное → обычная болтовня моделью для чата.

Модели для каждой цели берутся из `!ии_модель` / переменных окружения. Рекомендуемая
настройка для OmniRoute: `AI_MODEL=kr/minimax-m2.5` (чат), `AI_MODEL_CODING=kr/qwen3-coder-next`
(код). Для картинок нужна модель с эндпоинтом `/v1/images/generations` — в Kiro-провайдере
OmniRoute таких моделей может не быть, тогда генерация картинок будет недоступна.

### Диагностика подключения
Команда `!ии_тест` (администрация) отправляет пробный запрос к провайдеру и показывает
точную причину проблем: адрес, модель, HTTP-статус и кусок ответа. Если видите
`status=None` — бот вообще не достучался до провайдера (туннель лёг или адрес устарел).

### Локальный ИИ через OmniRoute (kr/claude-sonnet-4.5)
OmniRoute поднимает OpenAI-совместимый эндпоинт (по умолчанию `http://localhost:20128/v1`).
Задайте `AI_BASE_URL` = этот адрес + `/v1`, `AI_API_KEY` = ключ из «Менеджер API»,
`AI_MODEL` = `kr/claude-sonnet-4.5`.

> ⚠️ **Railway не видит ваш `localhost`.** `localhost:20128` внутри контейнера Railway
> указывает на сам контейнер, а не на ваш ПК. Чтобы облачный бот достучался до
> локального OmniRoute, откройте **публичный туннель** (в OmniRoute → «Конечные точки»:
> Cloudflare Quick Tunnel, Ngrok, Tailscale Funnel или «Облачный OmniRoute») и укажите
> в `AI_BASE_URL` **публичный** адрес туннеля + `/v1`. При локальном запуске бота на том
> же ПК `http://localhost:20128/v1` работает как есть.

> ⚠️ **Ссылки `*.trycloudflare.com` временные.** Cloudflare Quick Tunnel выдаёт новый
> случайный адрес при каждом перезапуске, поэтому URL, вбитый в переменные Railway,
> со временем «протухает». Тогда Cloudflare отдаёт HTML-страницу ошибки вместо JSON, и
> бот пишет в лог `status=None ... Expecting value: line 1 column 1 (char 0)`. Для
> постоянной работы используйте стабильный адрес: «Облачный OmniRoute», именованный
> Cloudflare Tunnel со своим доменом или Ngrok с фиксированным доменом — и не забывайте,
> что ваш ПК с OmniRoute должен быть **включён**, пока бот работает 24/7 на Railway.

### Упоминания участников
ИИ отвечает с тегом автора (`@имя, ...`) и может тегать других участников: если в
ответе встречается `@ник`, бот превращает его в настоящее упоминание. Массовые пинги
`@everyone`/`@here` намеренно запрещены.

### Персонаж матерится и шарит за русские мемы
По умолчанию системный промпт настроен на дерзкого персонажа, который свободно
использует русский мат и русские мемы. Но многое зависит от **выбранной модели**:
модели с жёсткой цензурой (например, `gpt-4o-mini` от OpenAI) будут смягчать мат и
часто отказываться. Для «живого» мата и русского сленга лучше подходят:

| Провайдер | `AI_BASE_URL` | Пример `AI_MODEL` | Где взять ключ |
|---|---|---|---|
| **DeepSeek** (дёшево, хороший русский) | `https://api.deepseek.com` | `deepseek-chat` | <https://platform.deepseek.com> |
| **OpenRouter** (много моделей, есть менее цензурные) | `https://openrouter.ai/api/v1` | `meta-llama/llama-3.1-70b-instruct` | <https://openrouter.ai/keys> |
| **Groq** (быстро, есть бесплатный лимит) | `https://api.groq.com/openai/v1` | `llama-3.3-70b-versatile` | <https://console.groq.com/keys> |

Мат — это стиль общения, а не травля: персонаж может дерзить и подкалывать, но
не устраивает реальную травлю, угрозы и не разжигает ненависть. Настроить тон
можно, отредактировав функцию `_ai_system_prompt` в `bot.py`.

### ⚠️ Важные предупреждения
Прежде чем включать «матерящегося» персонажа, учтите:

- **Контент 18+.** Мат и дерзкий тон подходят не всем. Включайте ИИ только на серверах/каналах,
  где это уместно, и предупредите участников. Хорошая практика — вынести бота в отдельный
  возрастной (age-restricted) канал.
- **Правила площадок.** За контент отвечает администрация сервера. Соблюдайте
  [правила сообщества Discord](https://discord.com/guidelines) и условия использования вашего
  ИИ-провайдера (например, [OpenAI Usage Policies](https://openai.com/policies/usage-policies/)).
- **Никогда не коммитьте ключи.** `AI_API_KEY` и `DISCORD_TOKEN` держите только в переменных
  окружения (Railway → Variables), а не в коде или `config.json` в репозитории. Если токен/ключ
  «засветился» (скриншот, лог, коммит) — немедленно перевыпустите его.
- **Стоимость API.** Почти все провайдеры платные и берут деньги за токены. Следите за расходами
  и при необходимости выставьте лимиты в кабинете провайдера. Антифлуд-кулдаун в боте
  (`AI_COOLDOWN_SECONDS`) снижает частоту запросов, но не отменяет оплату.
- **Модель может «сорваться».** ИИ иногда игнорирует рамки промпта и выдаёт неуместное.
  Держите включённым автомод и будьте готовы выключить ИИ командой `!ии выкл`.
- **Приватность.** Тексты сообщений уходят стороннему ИИ-провайдеру. Не обсуждайте через бота
  личные/секретные данные.

## Установка (локально)
1. Установите Python 3.9+.
2. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
3. В [Discord Developer Portal](https://discord.com/developers/applications) в разделе
   **Bot** включите два переключателя (Privileged Gateway Intents):
   - **MESSAGE CONTENT INTENT**
   - **SERVER MEMBERS INTENT**
4. Скопируйте `config.example.json` в `config.json` и вставьте токен, **либо**
   задайте переменную окружения `DISCORD_TOKEN`.
5. Пригласите бота на сервер с правами: *Управление каналами*, *Просмотр каналов*,
   *Отправка сообщений*, *Встраивание ссылок*, *Прикрепление файлов*,
   *Управление сообщениями* (для автомода), *Тайм-аут участникам* (муты),
   *Выгонять участников* (кики), *Банить участников* (баны).
   Важно: роль бота должна быть **выше** ролей тех, кого он должен наказывать.
6. Запустите бота:
   ```bash
   python bot.py
   ```

## Хостинг на Railway (бесплатно)
1. Залейте этот репозиторий в GitHub (уже сделано).
2. На [railway.com/new](https://railway.com/new) выберите **Deploy from GitHub repo**
   → выберите репозиторий с ботом.
3. Railway автоматически определит Python, поставит зависимости из
   `requirements.txt` и запустит процесс из `Procfile` (`worker: python bot.py`).
4. В настройках сервиса → **Variables** добавьте переменные:
   - `DISCORD_TOKEN` = ваш токен бота.
   - (необязательно) `PREFIX` = `!`.
   - (для ИИ) `AI_API_KEY` = ключ вашего провайдера; при необходимости `AI_BASE_URL`,
     `AI_MODEL`, `AI_BOT_NAME` (см. раздел «Настройка ИИ-собеседника»).
5. **Чтобы настройки не терялись при передеплое:** добавьте том (**Volume**) и
   смонтируйте его, например, в `/data`. Затем добавьте переменную
   `DATA_DIR=/data` — бот будет хранить `data.json` на этом томе.

> Файловая система Railway эфемерна: без тома `data.json` сбрасывается при каждом
> передеплое, и все настройки серверов пропадут. Переменная `DATA_DIR` решает это.

## Быстрая настройка на сервере Discord
Выполните по порядку (нужны права администратора сервера при первом запуске):

```
!роль_админ @Администрация          — назначить роль администрации
!роль_поддержки @Поддержка          — кто видит тикеты
!категория_тикетов <ID категории>   — категория Discord для каналов тикетов
!канал_логов #логи-тикетов          — куда писать логи
!канал_панели #создать-тикет        — где будет панель создания тикетов
!текст_панели Заголовок | Описание  — (необязательно) текст панели
!панель_тикетов                     — опубликовать панель создания тикетов
!панель_админ                       — открыть панель администрации
```

> ID категории Discord: включите «Режим разработчика» в настройках Discord,
> нажмите правой кнопкой на категорию → «Копировать ID».

### Модерация
| Команда | Описание |
|---|---|
| `!бан @участник [причина]` | забанить (администрация) |
| `!разбан <ID> [причина]` | разбанить (администрация) |
| `!кик @участник [причина]` | кикнуть (администрация) |
| `!мут @участник <время> [причина]` | мут/тайм-аут (поддержка) |
| `!размут @участник [причина]` | снять мут (поддержка) |
| `!варн @участник [причина]` | предупреждение (поддержка) |
| `!варны [@участник]` | показать предупреждения участника (поддержка) |
| `!снятьварн @участник [кол-во\|все]` | снять предупреждения (поддержка) |

Формат времени для мута: `30с`, `10м`, `2ч`, `1д` (латиница тоже: `30s`, `10m`, `2h`, `1d`).
Без единицы — минуты. Максимум по правилам Discord — 28 дней.

**Предупреждения (варны):** каждый `!варн` добавляет предупреждение и уведомляет
участника в ЛС. Когда набирается **3** предупреждения, бот прикрепляет к сообщению
кнопки **🔇 Мут / 🔨 Бан / 👢 Кик** — выбрать наказание может только модератор,
выдавший третий варн. После наказания счётчик обнуляется. Порог задаётся константой
`WARN_LIMIT` в `bot.py`.

### Автомод
| Команда | Описание |
|---|---|
| `!автомод` | панель настроек (вкл/выкл, пороги спама и мутов) |
| `!канал_модлогов <#канал>` | канал логов модерации/автомода (иначе — общий канал логов) |
| `!автомод_иммунитет <@роль>` | выдать/убрать иммунитет роли |

- **Анти-спам:** если участник отправляет N сообщений за T секунд — авто-мут и очистка
  сообщений (пороги настраиваются кнопкой «Настроить пороги»).
- **Анти-приглашения:** сообщение с приглашением в Discord (`discord.gg/...`,
  `discord.com/invite/...`) удаляется, автор получает мут. Обычные ссылки не трогаются.

## Файлы
- `bot.py` — код бота.
- `config.example.json` — шаблон конфигурации (скопируйте в `config.json`).
- `config.json` — токен и префикс (локально; в `.gitignore`).
- `data.json` — создаётся автоматически, хранит настройки и статистику каждого сервера (в `.gitignore`).
- `requirements.txt` — зависимости.
- `Procfile` — команда запуска для хостинга (Railway и т.п.).

## Примечания
- Настройки хранятся в `data.json` и не теряются при перезапуске; кнопки панелей
  тоже продолжают работать после перезапуска бота.
- Один пользователь не может открыть два тикета одной категории одновременно.
