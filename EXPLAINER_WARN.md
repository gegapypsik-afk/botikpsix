# Пояснительная записка: фикс ИИ-собеседника + система предупреждений (`!варн`)

Этот документ разбирает два изменения в `bot.py`:

1. **Почему бот отвечал «🤖 Что-то я подвис…»** и что с этим сделано.
2. **Новая система предупреждений** — команда `!варн`, а на третьем предупреждении бот
   предлагает модератору выбрать наказание: **мут / бан / кик**.

---

## 1. Диагноз «🤖 Что-то я подвис…»

### Background

Когда участник упоминает бота (`@Ботя, привет`), срабатывает обработчик `on_message` →
`maybe_ai_reply`. Внутри бот собирает историю канала и отправляет запрос в
OpenAI-совместимый API через функцию `ask_ai`. Адрес и ключ берутся из переменных
окружения (на Railway они и заданы):

```
AI_BASE_URL = https://api.deepseek.com
AI_MODEL    = deepseek-chat
AI_API_KEY  = sk-…
```

`ask_ai` шлёт `POST {AI_BASE_URL}/chat/completions` и, если статус ответа не `200`,
**бросает исключение**. Ловит его `maybe_ai_reply`, и в старом коде на **любую** ошибку
выдавалась одна и та же фраза:

```python
except Exception as exc:
    print(f"[ИИ] Ошибка запроса: {exc}")
    ...
    await message.reply("🤖 Что-то я подвис... попробуй тегнуть меня ещё раз чуть позже.")
```

> [!IMPORTANT]
> Ключевой вывод: «подвис» — это **не баг в коде общения**, а перехваченная ошибка от
> ИИ-провайдера. Реальная причина печаталась в лог (`[ИИ] Ошибка запроса: …`), но
> пользователю показывалась обтекаемая фраза, которая ещё и врала — предлагала
> «попробовать позже», хотя при неверном ключе или нуле на балансе повтор не поможет.

### Intuition

Адрес и модель в конфиге **корректны** (`https://api.deepseek.com/chat/completions` —
это валидный эндпоинт DeepSeek, а `deepseek-chat` — существующая модель). Значит,
запрос уходит куда надо, но провайдер отвечает ошибкой. Самые частые причины именно у
DeepSeek:

| Статус | Что значит | Лечится повтором? |
|-------|------------|-------------------|
| `402` | **Insufficient Balance** — на счёте DeepSeek нет средств (у него нет бесплатного тарифа) | ❌ нужно пополнить баланс |
| `401` | Ключ неверный/просрочен | ❌ нужно заменить `AI_API_KEY` |
| `403` | Доступ запрещён (ключ/модель/регион) | ❌ проверить настройки |
| `429` / `5xx` | Лимит или перегрузка провайдера | ✅ да, временно |

Судя по настройке (валидный адрес + модель, аккуратный ключ формата `sk-…`), самый
вероятный виновник — **402 Insufficient Balance**: у DeepSeek нет free-tier, и без
пополнения баланса каждый запрос падает с этой ошибкой.

> [!NOTE]
> Точную причину видно в **Railway → botik ticket → View logs**: ищите строку
> `[ИИ] Ошибка запроса (status=…): …`. Число в `status` прямо указывает на пункт из
> таблицы выше.

### Code

Теперь ошибка несёт HTTP-статус, а сообщение пользователю зависит от причины. Введён
маленький класс исключения:

```python
class AIError(RuntimeError):
    """Ошибка запроса к ИИ-провайдеру. Несёт HTTP-статус, если он известен."""
    def __init__(self, message: str, status: int | None = None):
        super().__init__(message)
        self.status = status
```

`ask_ai` теперь бросает `AIError(..., status=resp.status)` вместо «голого»
`RuntimeError`, а `maybe_ai_reply` различает постоянные и временные ошибки:

```python
except Exception as exc:
    status = getattr(exc, "status", None)
    print(f"[ИИ] Ошибка запроса (status={status}): {exc}")   # видно в Railway logs
    ...
    permanent = {
        401: "ключ ИИ неверный или просрочен",
        402: "на балансе ИИ-провайдера закончились средства",
        403: "провайдер отклонил запрос (проверьте ключ, модель и адрес API)",
        404: "модель или адрес API не найдены (проверьте AI_MODEL и AI_BASE_URL)",
    }
    if status in permanent:
        await message.reply(f"🤖 ИИ сейчас недоступен: {permanent[status]}. …")
    else:
        await message.reply("🤖 Что-то я подвис... попробуй тегнуть меня ещё раз чуть позже.")
```

Так временные сбои по-прежнему приглашают повторить, а неисправимые (баланс/ключ) прямо
говорят администратору, что чинить.

> [!WARNING]
> Токены из скриншотов (Discord-токен и ключ DeepSeek) засветились. Их стоит
> **перевыпустить**: Discord Developer Portal → Reset Token, и новый ключ DeepSeek —
> затем обновить переменные на Railway. Код менять для этого не нужно.

## 2. Система предупреждений `!варн`

### Background

В боте уже была модерация: `!бан`, `!кик`, `!мут`, `!размут`. Каждая команда:
проверяет права через декоратор (`@admin_only` / `@staff_only`), проверяет иерархию
ролей через `can_moderate`, выполняет действие и пишет в модлог `mod_log`. Настройки
каждого сервера лежат в `data.json` и описаны в `_default_guild()`; при старте есть
«мягкая миграция» — недостающие ключи добавляются автоматически.

Чего не хватало — **накопительных предупреждений**: выдать варн, посчитать их и на
пороге предложить наказание.

### Intuition

Идея простая, как записная книжка модератора:

```
!варн @Тролль спам      →  Тролль: 1/3
!варн @Тролль флуд      →  Тролль: 2/3
!варн @Тролль токсик    →  Тролль: 3/3  →  бот: «Порог! Выбери наказание 👇»
                                            [🔇 Мут] [🔨 Бан] [👢 Кик]
```

На третьем варне под сообщением появляются три кнопки. Нажать их может **только тот
модератор**, что выдал третий варн (чтобы посторонние не решали за него). После
наказания счётчик обнуляется — человек начинает с чистого листа.

> [!NOTE]
> Порог вынесен в константу `WARN_LIMIT = 3`. Хочется «5 варнов» — меняете одно число,
> и все тексты и логика подстроятся автоматически.

Данные хранятся по-серверно и по-пользовательски:

```json
"warns": {
  "20": [
    {"mod_id": 10, "reason": "спам",   "ts": "2026-08-05T12:00:00+00:00"},
    {"mod_id": 10, "reason": "флуд",   "ts": "2026-08-05T12:05:00+00:00"}
  ]
}
```

### Code

**1. Хранилище.** В `_default_guild()` добавлен ключ `"warns": {}`. Старые серверы
получат его автоматически благодаря существующей миграции в `Storage.guild()`.

**2. Переиспользуемая проверка иерархии.** Логика из `can_moderate` вынесена в чистую
функцию, чтобы её могли использовать и текстовые команды, и кнопки (у кнопок нет `ctx`):

```python
def _moderation_block_reason(guild, author, member):
    """Причина, по которой нельзя наказать участника, либо None если можно."""
    if member.id == author.id:            return "❌ Нельзя применить это к самому себе."
    if member.id == guild.me.id:          return "❌ Нельзя применить это ко мне 🙂"
    if member.id == guild.owner_id:       return "❌ Нельзя наказать владельца сервера."
    if author.id != guild.owner_id and member.top_role >= author.top_role:
        return "❌ У этого участника роль выше или равна вашей."
    if member.top_role >= guild.me.top_role:
        return "❌ Роль участника выше моей — …"
    return None
```

`can_moderate` теперь просто обёртка над этой функцией.

**3. Команда `!варн`.** Проверяет права (`@staff_only`) и иерархию, добавляет запись,
шлёт участнику ЛС, а на пороге вместо обычного эмбеда прикрепляет панель наказаний:

```python
@bot.command(name="варн", aliases=["предупредить", "warn"])
@staff_only()
async def warn_cmd(ctx, member, *, reason="Причина не указана"):
    if not await can_moderate(ctx, member):
        return
    gdata = storage.guild(ctx.guild.id)
    warns = _warns_list(gdata, member.id)
    warns.append({"mod_id": ctx.author.id, "reason": reason,
                  "ts": datetime.now(timezone.utc).isoformat()})
    count = len(warns)
    storage.save()
    ...
    if count >= WARN_LIMIT:
        view = PunishmentView(member, ctx.author, gdata)
        view.message = await ctx.reply(embed=embed, view=view)
    else:
        await ctx.reply(embed=embed)
    await mod_log(ctx.guild, gdata, embed)
```

**4. Панель выбора наказания `PunishmentView`.** Три кнопки. `_guard` пускает только
автора третьего варна и перепроверяет иерархию на момент нажатия. `finish` — общий
хвост: обнулить варны, погасить кнопки, записать в модлог.

```python
class PunishmentView(discord.ui.View):
    def __init__(self, member, moderator, gdata):
        super().__init__(timeout=180)
        self.member, self.moderator, self.gdata = member, moderator, gdata
        self.message = None

    async def _guard(self, interaction):
        if interaction.user.id != self.moderator.id:
            await interaction.response.send_message("⛔ Наказание выбирает …", ephemeral=True)
            return False
        block = _moderation_block_reason(interaction.guild, self.moderator, self.member)
        ...

    async def finish(self, guild, embed):
        self.gdata.setdefault("warns", {}).pop(str(self.member.id), None)  # сброс
        storage.save()
        self._disable(); ...; await mod_log(guild, self.gdata, embed)

    @discord.ui.button(label="Мут", emoji="🔇", …)
    async def mute_btn(...):  # открывает модалку с длительностью
    @discord.ui.button(label="Бан", emoji="🔨", style=danger)
    async def ban_btn(...):   # member.ban(...)
    @discord.ui.button(label="Кик", emoji="👢", style=primary)
    async def kick_btn(...):  # member.kick(...)
```

Кнопка **Мут** открывает модалку `WarnMuteModal` с полем длительности (по умолчанию
`1ч`), потому что для тайм-аута нужно указать срок; **Бан** и **Кик** срабатывают сразу.

**5. Вспомогательные команды.** Для полноты добавлены `!варны [@user]` (посмотреть
список) и `!снятьварн @user [кол-во|все]` (снять). И обновлён раздел модерации в
`!помощь`.

### Verification

Так как окружение без Discord-сети, поведение проверено офлайн-харнессом с фейковыми
объектами (`ctx`, `guild`, `member`, `interaction`), который импортирует реальный
`bot.py` и вызывает настоящие функции. Покрыто **23 проверки**, все зелёные:

- `_default_guild()` содержит `warns`;
- иерархия: нельзя варнить себя / бота / владельца / вышестоящего, можно — нижестоящего;
- накопление: 1-й и 2-й варн — без панели, 3-й — появляется `PunishmentView` с 3 кнопками;
- нажатие **Бан** → участник забанен, варны обнулены, кнопки погашены;
- посторонний не может нажать кнопки (получает ephemeral-отказ);
- `!снятьварн 1` снимает один, `!снятьварн все` — очищает;
- `AIError` несёт `status`; при `402` бот отвечает про **баланс**, а не «подвис».

Также проходит `python -m py_compile bot.py`.

**Ручная проверка на сервере (QA):**
1. Дайте себе роль поддержки/админа (или права управления сервером).
2. `!варн @тест причина` дважды — увидите счётчик `1/3`, `2/3`.
3. Третий `!варн @тест` — под сообщением появятся кнопки **Мут / Бан / Кик**.
4. Нажмите **Мут** → введите `10м` → участник получает тайм-аут, счётчик обнуляется.
5. `!варны @тест` — список пуст; `!снятьварн @тест все` на непустом — очищает.
6. Убедитесь, что роль бота **выше** роли наказываемого и у бота есть права
   «Банить/Выгонять/Тайм-аут».

### Alternatives

**А. Хранить только счётчик (число), а не историю варнов.**

| Плюсы | Минусы |
|-------|--------|
| Проще структура данных | Не видно, кто и за что варнил |
| Меньше места в `data.json` | Нельзя показать список в `!варны` |

Выбрана история (список), т.к. модерации важен контекст «кто/когда/почему».

**Б. Автоматически наказывать на 3-м варне без выбора (например, всегда бан).**

| Плюсы | Минусы |
|-------|--------|
| Ноль кликов, полностью автоматом | Нет гибкости под ситуацию |
| Нельзя «передумать» | Может забанить за мелочь |

Пользователь явно просил **выбор** мут/бан/кик — поэтому реализована панель с кнопками.
